# 파워리프팅 트래커 (단일 HTML) — 진행 내역

> 대상 파일: `파워리프팅-트래커-32.html` (React+Babel CDN, 단일파일, 메인 엔진 앱과 별개)
> 배포: https://aa26178787.github.io/powerlifting/tracker.html (public/tracker.html, 메인 앱과 같은 Pages에 정적 서빙)
> DB: Firebase Firestore (`powerlifting/main` 문서, 기기 간 실시간 동기화)
> 최종 갱신: 2026-07-21

## 배경
기존엔 `window.storage`(존재하지 않는 API)를 써서 새로고침/재접속 시 데이터가 날아가는 상태였음. 이번 세션에서 영속화·기기 간 동기화·과거 기록 수정·TM 자동조절 로직까지 순차 추가.

## 주요 변경

1. **데이터 영속화**: `window.storage` → `localStorage` 교체 (새로고침/재접속 유지)
2. **과거 날짜 수정 가능**: 오늘 탭에서 과거 날짜 선택 시 읽기전용 카드 → 오늘과 동일한 인라인 입력(`TodayCard`)으로 교체, `date`/`cycle`/`week` prop을 일반화해 임의 날짜 기준 저장·매칭
3. **기록 탭 날짜 입력 버그 수정**: 수동 입력이 항상 오늘 날짜로만 저장되던 문제 → 이후 아예 수동 세트입력 폼 제거(오늘 탭 인라인 입력으로 통합)
4. **세트 위치 밀림 버그 수정**: 로그를 배열 위치(idx)로만 매칭해 중간 세트 삭제 시 백오프 기록이 앞으로 밀리던 문제 → 저장 시 `setIdx` 고정 태그 부여, 그 값으로 매칭
5. **3주차 싱글 실시간 연동**: 오늘 탭에서 "기입" 싱글 세트 저장 시 사이클 탭의 싱글 실측 필드(`S.singles`)에 자동 반영 → 92%/86.5% 백오프 무게 즉시 재계산 (단, 조작 대상이 현재 진행 사이클일 때만 반영해 과거 사이클 오염 방지)
6. **기기 간 동기화**: Firebase Firestore 연결 (`localStorage`는 오프라인 캐시로 유지), Firestore 규칙은 `powerlifting/main` 문서만 개방
7. **GitHub Pages 배포**: `public/tracker.html`로 정적 배포, push 시 기존 `deploy.yml`이 자동 빌드/배포 — **이후 수정은 항상 `public/tracker.html` 동기화 + commit + push까지 자동 진행**(사용자 지시)
8. **오늘 탭 UX**: 사이클 28일(1~4주차) 전체를 날짜 스트립에 노출(과거 수정 + 미래 루틴 미리보기), 주차별 카드형 컨테이너로 시각 분리, 오늘 위치 자동 스크롤
9. **날짜별 기록 내보내기**: 설정 탭의 "전체 기록 내보내기"(최근 30개, AI 채팅 붙여넣기용) 제거 → 오늘 탭 상단에 "그 날짜 기록만" 내보내는 버튼으로 교체, 무게 없는 보조운동은 방어적으로 필터링
10. **기록 탭**: 날짜 최신순 정렬 + 날짜별 섹션 헤더
11. **중딥 백오프 세트 수 수정**: 4세트 → 3세트, "탑1+백3" 라벨 → "탑1+백2"
12. **TM(트레이닝 맥스) 사이클 전환 로직** (스쿼트·벤치·데드 전용, 중딥/중량풀업은 기존 방식 유지):
    - **신호1 (완전 자동)**: AMRAP 세트(1/2주차 3세트째, 3주차 86.5%) 초과렙 → 인상폭 배율(0/0.5/1/2×) 자동 계산, 사이클마다 누적 적용
    - **신호2 (승인 필요)**: 3주차 고정렙 세트(기입싱글·92%) RPE 여유 → "TM 재산정 권장" 배지만 표시, 자동 반영 없음
    - **재산정 승인 플로우**: confirm 다이얼로그 → 승인 시 TM 숫자를 직접 덮어쓰지 않고 트리거 세트의 무게/렙/RPE를 TM 입력 필드에 대입 → e1RM·적용TM 기존 공식으로 재계산 → 재기준(baseCycle) 이후 신호1 인상폭이 그 위에 얹힘 (재산정 → 인상폭 순서 보장)

## 알려진 이슈 / 참고
- 사용자 제공 스펙 예시 중 "145×1@RPE7.5, 처방8 대비 -1.5" 부분은 산술상 diff=0.5이므로 스펙 문서 자체의 예시 오타로 보임 (코드는 문서화된 공식 `처방RPE−실제RPE≥1.5` 그대로 구현).
- Firestore 규칙: `powerlifting/main` 문서만 개방된 테스트 성격 규칙 — apiKey가 html에 노출되어 있으므로 해당 문서 자체는 사실상 공개.
